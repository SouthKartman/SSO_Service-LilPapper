APPLICATION MANAGEMENT

Управление приложениями

Регистрация OAuth 2.0 / OpenID Connect клиентов через административную панель SSO.

К документации

STEP 01

Подготовьте параметры

Перед регистрацией

Определите отображаемое название, уникальный Client ID и точный Redirect URI — адрес callback, на который SSO вернёт браузер после авторизации.

Безопасность

Redirect URI должен принадлежать вашему приложению. Не используйте адреса, которыми вы не управляете.

STEP 02

Создайте клиента

01

Откройте панель

Войдите под аккаунтом с ролью Admin и откройте /Admin/Applications.

02

Заполните поля

Укажите название, уникальный Client ID, тип клиента и Redirect URI.

03

Проверьте настройки

Client ID и Redirect URI в приложении должны совпадать с зарегистрированными значениями.

CLIENT TYPES

Public и Confidential

Public

Для браузерных клиентов, которые не могут безопасно хранить секрет. Используйте Authorization Code Flow с PKCE.

01
Confidential

Для серверных приложений, способных безопасно хранить клиентские секреты. Не помещайте секрет в публичный frontend-код.

02

SCOPES & CALLBACK

Scopes и Redirect URI

openid нужен для OpenID Connect. Дополнительные scopes, например profile и email, запрашивайте только если они нужны приложению и разрешены настройками клиента.

Проверка

Сверьте схему, домен, порт, путь и завершающий слеш URI.
