ADMINISTRATION

Управление приложениями

Руководство по регистрации сторонних приложений, настройке доступа к SSO и проверке параметров клиента.

Открыть панель приложений → Руководство по интеграции

01 / ACCESS

Доступ к панели

Управление клиентами доступно через административную панель SSO. Для работы с ней необходима учётная запись с соответствующей административной ролью.

Страница управления приложениями: /Admin/Applications.

02 / REGISTRATION

Создание клиента

  1. Откройте раздел управления приложениями.
  2. Укажите название приложения.
  3. Введите уникальный Client ID.
  4. Выберите тип клиента: Public или Confidential.
  5. Укажите Redirect URI, зарегистрированный в приложении.
  6. Выберите необходимые разрешения Profile и Email.
  7. Сохраните форму и проверьте появление записи в списке.
Client ID

Это идентификатор приложения, а не пользователя. Он должен быть уникальным среди зарегистрированных клиентов.

03 / CLIENT TYPES

Типы клиентов

PUBLIC

Public client

Клиент, который не может безопасно хранить секрет. Например, приложение в браузере или нативное приложение. Для Authorization Code Flow используется PKCE.

CONFIDENTIAL

Confidential client

Клиент, способный хранить секрет на защищённом сервере. Секрет нельзя помещать в публичный HTML или JavaScript.

04 / REDIRECT URI

Настройка Redirect URI

Redirect URI определяет адрес, на который SSO возвращает браузер после обработки запроса авторизации.

  • Адрес должен быть абсолютным HTTP/HTTPS URL.
  • HTTP допускается только для loopback-адресов в текущей проверке админки.
  • Для остальных адресов используй HTTPS.
  • Redirect URI в запросе должен совпадать с зарегистрированным адресом.
Безопасность

Не указывай произвольные адреса перенаправления, которыми ты не управляешь. Это может привести к утечке кода авторизации.

05 / VERIFICATION

Проверка регистрации

  1. Убедитесь, что клиент появился в списке.
  2. Проверьте Client ID, тип и Redirect URI.
  3. Запустите отдельное тестовое приложение с этим Client ID.
  4. Проверьте Authorization Code Flow с PKCE.
  5. Убедитесь, что неправильный Redirect URI отклоняется.

Создание записи в базе само по себе не подтверждает, что стороннее приложение успешно проходит авторизацию.

06 / REMOVAL

Удаление клиента

Удаление регистрации запрещает использовать её как действующий клиент для новых запросов авторизации. Перед удалением проверьте, что приложение больше не использует эту регистрацию.

Удаление регистрации и отзыв уже выданных токенов — разные задачи. После удаления необходимо отдельно проверить поведение ранее выданных токенов и связанных авторизаций.
