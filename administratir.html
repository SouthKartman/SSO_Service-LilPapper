ADMINISTRATOR SETUP

Создание администратора

Порядок создания учётной записи и назначения ей административной роли через PostgreSQL.

01 / USER REGISTRATION

Создание учётной записи

  1. Запустите SSO-сервис.
  2. Откройте существующую тестовую страницу авторизации.
  3. Зарегистрируйте нового пользователя с нужными данными.
  4. Выйдите из тестовой учётной записи, если необходимо.
  5. Убедитесь, что новая запись появилась в таблице пользователей.

Тестовая страница предназначена для проверки авторизации. Само наличие учётной записи не означает, что пользователь автоматически получает права администратора.

02 / DATABASE

Поиск пользователя в PostgreSQL

Подключитесь к той базе данных, которую использует SSO, и найдите созданную учётную запись в таблице Identity. 

SELECT
    "Id",
    "UserName",
    "Email"
FROM "AspNetUsers"
WHERE "UserName" = 'admin@example.com';
Перед выполнением

Замените admin@example.com на фактическое значение UserName созданной учётной записи. В стандартном ASP.NET Core Identity имя пользователя и email могут храниться отдельно.

03 / ROLE

Проверка роли администратора

В стандартной схеме ASP.NET Core Identity роли хранятся в таблице AspNetRoles, а связь пользователя с ролью — в AspNetUserRoles.

Сначала проверьте, существует ли нужная роль:

SELECT "Id", "Name", "NormalizedName"
FROM "AspNetRoles"
ORDER BY "Name";

Используйте точное название роли, которое проверяет авторизация административных Razor Pages. Не создавайте роль с другим названием, иначе доступ может не появиться.

04 / ASSIGNMENT

Назначение роли

Перед назначением роли определите идентификатор пользователя и идентификатор существующей роли. Не подставляйте значения наугад и не изменяйте пароль или другие поля Identity напрямую.

Рекомендуемый порядок

Найдите пользователя, найдите административную роль, проверьте связь пользователя с ролью и только затем добавляйте её при отсутствии связи.

Конкретную SQL-команду для назначения роли следует выполнять после подтверждения фактического названия роли и структуры таблиц в вашей базе.

05 / VERIFICATION

Проверка доступа

  1. Выйдите из SSO.
  2. Войдите под учётной записью, которой назначили роль.
  3. Откройте административную панель.
  4. Проверьте доступ к управлению приложениями.
  5. Войдите под обычным пользователем и убедитесь, что административные разделы ему недоступны.
Важно

Назначение роли предоставляет административные полномочия. Выполняйте эту операцию только для доверенной учётной записи и только в нужной базе данных.
